# 지침: 픽셀 아트 에디터 — Plan 단계

## 목표
`/apps/pixel-art/`에 들어갈 픽셀 아트 에디터 웹앱의 구현 계획을 세우고
`/apps/pixel-art/spec.md`에 저장한다. **이 단계에서는 코드를 작성하지 않는다.**
계획만 세운다.

## 요구사항 (사용자 요청)
- 16x16 격자에 도트를 찍어서 그림을 그리는 픽셀 아트 에디터
- 완성하면 PNG 파일로 저장(다운로드) 가능
- 색상 팔레트 필요

## 제약 (CLAUDE.md 규칙)
- 프레임워크 없이 순수 HTML/CSS/JS
- 모든 파일은 `/apps/pixel-art/` 폴더 안에 자체 완결(블로그의 다른 파일 건드리지 않음)
- 외부 라이브러리 최소화 (CDN은 허용되지만 이 정도 규모엔 불필요할 가능성 높음)
- 모바일에서도 사용 가능해야 함 (터치로 그리기 포함)

## spec.md에 포함할 내용
1. 파일 구조 (`/apps/pixel-art/index.html`, `style.css`, `script.js` 등)
2. 16x16 격자 표현 방법
   - 상태를 어떻게 저장할지 (예: 16x16 문자열 배열, 각 칸의 색상값)
   - DOM 렌더링 방식 (16x16 = 256개 div/버튼을 CSS Grid로 배치하는 방식 등)
3. 그리기 상호작용
   - 마우스 클릭으로 칠하기
   - 마우스 버튼을 누른 채 드래그하면 지나가는 칸들이 연속으로 칠해지는 동작
   - 모바일 터치로도 동일하게 그릴 수 있어야 함 (touchstart/touchmove 처리,
     스크롤과 충돌하지 않도록 처리 방법 포함)
4. 색상 팔레트
   - 프리셋 색상 스와치 여러 개 (몇 개, 어떤 색들인지 구체적으로)
   - 커스텀 색상 선택 UI (`<input type="color">` 등)
   - 현재 선택된 색상을 시각적으로 표시하는 방법
   - 지우개 도구(칸을 빈 상태/배경색으로 되돌리기)
5. PNG 저장 기능
   - 화면에 보이는 확대된 격자와 별개로, 실제 저장에 사용할 `<canvas>`를
     어떻게 구성할지 (16x16 그대로 저장할지, 몇 배율로 확대해서 저장할지
     구체적으로 결정하고 이유를 설명)
   - `canvas.toDataURL('image/png')` (또는 `toBlob`)과 `<a download>`를
     이용한 다운로드 트리거 방식
6. 전체 지우기(Clear) 버튼
7. UI 레이아웃 및 반응형 설계
   - 데스크톱/모바일에서 격자와 팔레트가 어떻게 배치되는지
   - 시맨틱 HTML, 다크모드는 이 앱 범위에서는 불필요(2048과 마찬가지로
     자체 완결된 고정 팔레트 UI로 충분함을 명시)
8. 간단한 테스트 계획 (Review 단계에서 확인할 체크리스트: 그리기, 색상
   변경, 드래그로 연속 칠하기, 지우기, PNG 다운로드, 모바일 터치, 반응형 등)

## 출력
`/apps/pixel-art/spec.md` 파일 하나만 작성한다. 다른 파일은 만들지 않는다.
작성 후 spec.md의 핵심 요약을 3~5문장으로 응답해라.
