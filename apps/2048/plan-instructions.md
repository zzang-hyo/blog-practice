# 지침: 2048 게임 — Plan 단계

## 목표
`/apps/2048/`에 들어갈 2048 퍼즐 게임 웹앱의 구현 계획을 세우고
`/apps/2048/spec.md`에 저장한다. **이 단계에서는 코드를 작성하지 않는다.**
계획만 세운다.

## 요구사항 (사용자 요청)
- 방향키(↑↓←→)로 숫자 타일을 밀어서 합치는 2048 게임
- 점수판(현재 점수, 가능하면 최고 점수도) 표시

## 제약 (CLAUDE.md 규칙)
- 프레임워크 없이 순수 HTML/CSS/JS
- 모든 파일은 `/apps/2048/` 폴더 안에 자체 완결(블로그의 다른 파일 건드리지 않음)
- 외부 라이브러리 최소화 (CDN은 허용되지만 이 정도 게임엔 불필요할 가능성 높음)
- 모바일에서도 사용 가능해야 함 (터치 스와이프 등 고려)

## spec.md에 포함할 내용
1. 파일 구조 (`/apps/2048/index.html`, `style.css`, `game.js` 등)
2. 게임 로직 설계
   - 4x4 그리드 상태 표현 방법
   - 방향별 이동/합치기(merge) 알고리즘 개요 (한 번의 합치기만 허용하는 규칙 등)
   - 새 타일 생성 규칙(빈 칸에 2 또는 4가 나타나는 확률)
   - 승리 조건(2048 타일 등장) / 패배 조건(더 이상 이동 불가) 처리
3. UI/스타일 설계
   - 그리드/타일 레이아웃 (CSS Grid 등)
   - 타일 값별 색상 팔레트 (라이트 배경 기준, 이 앱은 블로그의 다크모드
     시스템과는 독립적으로 자체 완결된 스타일을 가짐)
   - 애니메이션 여부 (있으면 좋지만 필수 아님, 간단하게)
4. 점수판 설계
   - 현재 점수 계산 방식(합쳐질 때마다 합쳐진 값만큼 가산)
   - 최고 점수는 `localStorage`에 저장해 새로고침 후에도 유지
5. 입력 처리
   - 키보드 방향키(메인 요구사항)
   - 모바일 대응: 터치 스와이프 제스처도 지원 (요구사항의 "모바일에서도
     사용할 수 있어야 한다"를 만족시키기 위함)
6. 새 게임 버튼, 게임오버/승리 시 안내 UI
7. 간단한 테스트 계획 (Review 단계에서 확인할 체크리스트)

## 출력
`/apps/2048/spec.md` 파일 하나만 작성한다. 다른 파일은 만들지 않는다.
작성 후 spec.md의 핵심 요약을 3~5문장으로 응답해라.
