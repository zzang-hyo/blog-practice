# 2048 게임 — Review 결과

검증 환경: `python3 -m http.server 8091` (apps/2048 디렉터리) + Playwright(Chromium),
데스크톱 뷰포트(1024x800), 모바일 뷰포트(375x700, 400x800/touch) 별도 컨텍스트로 검증.
게임 로직은 `game.js`에 정의된 함수(`move`, `slideAndMergeRow`, `checkGameOverCondition` 등)를
브라우저 컨텍스트 안에서 상태를 직접 세팅해 호출하는 방식으로 검증했다(코드 수정 없음).

## spec.md 체크리스트 결과

**기본 동작**
- [x] 페이지 로드 시 보드에 타일이 정확히 2개 생성된다.
- [x] 콘솔에 에러/경고가 없다.

**이동/합치기 로직**
- [x] 방향키 4방향(↑↓←→) 모두 타일이 올바른 방향으로 밀린다.
- [x] 같은 값의 인접 타일이 합쳐지고, 합쳐진 값이 두 배가 된다.
- [x] 한 번의 이동에서 타일 하나가 두 번 이상 합쳐지지 않는다 (`[2,2,2,2]` → `[4,4,0,0]` 확인, `[8,0,0,0]` 아님).
- [x] 이동해도 보드가 변하지 않는 경우 새 타일이 생성되지 않는다.
- [x] 유효한 이동 후에는 반드시 새 타일이 정확히 1개 생성된다.

**점수판**
- [x] 타일이 합쳐질 때마다 점수가 합쳐진 값만큼 정확히 증가한다.
- [x] 최고 점수가 현재 점수보다 낮아지면 즉시 갱신된다.
- [x] 페이지를 새로고침해도 최고 점수가 유지된다(localStorage `2048-best-score` 확인).
- [x] "새 게임"을 눌러도 최고 점수는 초기화되지 않고 현재 점수만 0이 된다.

**승리/패배**
- [x] 2048 타일이 생성되면 승리 오버레이가 뜬다.
- [x] 승리 오버레이에서 "계속하기"를 누르면 게임이 계속되고, 오버레이가 다시 뜨지 않는다.
- [x] 보드가 가득 차고 더 이상 합칠 수 있는 인접 쌍이 없으면 게임 오버 오버레이가 뜬다.
- [x] 게임 오버 상태에서는 방향키/스와이프 입력이 무시된다("다시 시작" 버튼만 동작).

**입력 처리**
- [x] 방향키 입력 시 페이지가 스크롤되지 않는다(`preventDefault` 확인, `scrollY` 불변 확인).
- [x] 모바일 뷰포트(터치 이벤트 디스패치)에서 스와이프가 정상 동작한다(오른쪽 스와이프로 타일 이동 확인).
- [x] 짧은 탭(스와이프 임계값 30px 미만)에서는 이동이 발생하지 않는다.

**반응형/스타일**
- [x] 375px 너비에서 가로 스크롤 없음, 보드(`#board`)가 뷰포트 안에 완전히 들어감(width 343px, left 16px).
- [x] 타일 자릿수별 `data-digits` 클래스와 그에 대응하는 `font-size` 축소 규칙이 존재해 4자리 숫자도 셀을 벗어나지 않음(코드 검토 + 렌더 확인).
- [x] `color-scheme: light` 고정 + `prefers-color-scheme` 미사용. OS `colorScheme: 'dark'`로 강제해도 `body` 배경색이 `rgb(250,248,239)`(`#faf8ef`, 라이트 팔레트)로 유지됨을 확인.

**독립성**
- [x] `apps/2048/`의 세 파일(index.html, style.css, game.js)만으로 동작. `index.html`에 블로그 루트로 돌아가는 선택적 링크(`../../index.html`) 한 줄 외에는 블로그 파일(build.js, templates/, posts/, assets/)에 대한 참조가 전혀 없음(grep 확인). 빌드 도구/CDN 의존성 없음.

## 발견한 문제 및 수정 내역

코드 리뷰와 위 브라우저 검증 전 과정에서 spec.md 체크리스트를 위배하는 버그를 발견하지 못했다.
방향 변환(`transpose`/`reverseRows`)의 합성이 상/하/좌/우 모두 정확히 대응됨을 좌표 단위로
직접 검증했고, merge 로직(`slideAndMergeRow`)이 한 이동당 타일 하나를 최대 1회만 합치는 것도
확인했다. **따라서 세 파일 중 어느 것도 수정하지 않았다.**

참고로 다음은 spec.md 체크리스트 범위 밖의 사소한 관찰이며 버그로 분류하지 않았다(수정하지 않음):
- 승리 오버레이가 떠 있는 동안에도 전역 `keydown` 리스너는 계속 동작해 오버레이 뒤에서 보드가
  바뀔 수 있다. spec.md는 이 경우에 대한 입력 차단을 요구하지 않고("게임 오버 상태"에서만 요구),
  체크리스트에도 해당 항목이 없어 범위 밖으로 판단했다.

## 최종 결론

**배포(Embed 단계로 진행) 가능.** spec.md의 테스트 계획 체크리스트 전 항목이 PASS이며,
코드 수정 없이 그대로 사용 가능한 상태다.
